# Definition of Ready

Before implementation begins, establish the applicable items:

- A concrete objective and observable acceptance criteria.
- Explicit non-goals and boundaries for the change.
- Affected applications, packages, contracts, data, and user roles.
- Existing implementation and tests discovered through graph tools or targeted searches.
- Important failure modes, edge cases, privacy concerns, and security threats.
- A verification plan covering focused tests and affected integration points.
- Required tools, environment access, fixtures, and external dependencies.
- Any payment, migration, production, or AI-configuration changes identified and approved by Project owner (ABADO).

Small, low-risk tasks may satisfy these points mentally. Record them when the work is complex, cross-cutting, security-sensitive, or likely to require handoff.
