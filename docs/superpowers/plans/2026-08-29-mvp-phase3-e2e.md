# MVP Phase 3 — Critical E2E Flows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove web-first MVP buyer/seller journey end-to-end via Playwright + API — registration through escrow release with auth, messaging, and admin ops — on clean staging build.

**Architecture:** Playwright 1.50+ with POM, fixtures for auth/data, parallel projects (chromium/firefox/webkit), baseURL from `NEXT_PUBLIC_API_BASE_URL`, webServer `pnpm dev:web` for local, `BASE_URL` env for staging, artifacts (screenshot/trace/video) on failure, API helpers via `ForumoApiClient` for seeding.

**Tech Stack:** Playwright, Next.js 15, NestJS, Prisma, @forumo/shared, Mailpit (dev email)

**Spec:** `docs/product/mvp-launch-capability.md` (Critical E2E flows) + `docs/TESTING.md`

## Global Constraints

- All critical flows must be server-side authorized (no UI-only gating).
- Tests must be isolated (fresh user per test via API), no shared state, no `page.waitForTimeout`.
- `NEXT_PUBLIC_USE_API_MOCKS=false` for E2E (real backend).
- Auctions, advanced inventory, multi-market deferred — no tests for those.
